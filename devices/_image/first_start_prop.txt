# ---- First start: one setting for every Lumen OS image (devices/_image/first_start_prop.txt)
# The language, time and time zone a projector starts with, the same on every model (owner 2026-11-13: English, the
# time and the time zone from the network, no fixed zone). This file is the only place that sets them: the image
# builder puts it at the end of /system/product/etc/build.prop of every image and drops any earlier line of these keys
# there (devices/_image/checks/first_start.py apply), and every image is checked (first_start.py check).
# Why it wins: Android 14 init reads system, system_ext, vendor, odm and then product (property_service.cpp,
# PropertyLoadBootDefaults), and a later line of a key replaces an earlier one, so these lines beat the stock vendor
# build.prop of every XGIMI model (persist.sys.language=zh, persist.sys.country=CN, persist.sys.timezone=Asia/Shanghai,
# ro.product.locale=zh-CN) without writing the vendor partition. A language or time zone the user picks (Lumen Setup,
# Settings) is saved in /data and wins from then on.
# Language: zygote takes persist.sys.locale, then persist.sys.language with country and localevar, then
# ro.product.locale (AndroidRuntime.cpp readLocale). The vendor's language pair is emptied, English is the product
# locale.
ro.product.locale=en-US
persist.sys.locale=
persist.sys.language=
persist.sys.country=
persist.sys.localevar=
# Time zone: none fixed (the vendor's Asia/Shanghai is emptied). Lumen Setup takes the zone from the network (IP
# lookup). Until a zone is set the clock runs on UTC. Automatic time and automatic time zone stay on: they are the
# SettingsProvider defaults def_auto_time and def_auto_time_zone, true in AOSP, and no overlay of an image changes them
# (first_start.py check reads every overlay).
persist.sys.timezone=
# Language lists without the pseudo-locales en-XA and ar-XB (TvSettings lists them once developer options are on).
# A negative filter: LocalePicker also tests it against the user's own locale.
ro.localization.locale_filter=^(?!en-XA$|ar-XB$)
# ---- Display refresh rate: the stock rule on every image
# Android 14 QPR3 SurfaceFlinger turns content detection on by default (initScheduler: the default follows
# enable_frame_rate_override, true), while the stock XGIMI SurfaceFlinger of every model runs without it (stock dumps:
# HB "Content detection: off", Z9X "ContentDetection=false"; every Lumen dump: true). With it on, SurfaceFlinger picks
# the mode from how often UI layers draw, and on a model with two modes nothing brings it back to the default: a Lumen
# HB (3840x2160 at 50 and 60 Hz, system default 60 Hz, no app request) ran 11 h 24 min of 12 h at 50 Hz, the stock HB
# stayed at 60 Hz on Home and on an HDMI input. Off, a rate an app asks for (Surface.setFrameRate, a 25 fps film in
# ExoPlayer) still switches the mode as on stock, and every other screen stays at the default mode.
ro.surface_flinger.use_content_detection_for_refresh_rate=false
